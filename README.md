# ระบบคิวและรับประทานอาหารในร้านบุฟเฟต์

เว็บแอปสำหรับจัดการคิว โต๊ะ เมนู คำสั่งซื้อ การชำระเงิน และการทำงานของพนักงานร้านบุฟเฟต์ รองรับภาษาไทยและภาษาอังกฤษ

## ความสามารถหลัก

- ลูกค้ารับคิวและตรวจสอบสถานะคิว
- เลือกโต๊ะตามจำนวนผู้ใช้บริการและโซนที่นั่ง
- เปิดเซสชันโต๊ะ สั่งอาหาร และติดตามสถานะคำสั่งซื้อ
- พนักงานครัวและพนักงานบริการจัดการคำสั่งซื้อและโต๊ะ
- ผู้ดูแลจัดการเมนู พนักงาน การตั้งค่าร้าน และรายงาน
- แสดงคิวบนหน้าจอสาธารณะ
- รองรับการเชื่อมต่อ MongoDB ผ่าน Mongoose

## เทคโนโลยี

- Node.js และ Express
- MongoDB Atlas และ Mongoose
- HTML, CSS, Tailwind CSS และ JavaScript
- Socket.IO สำหรับเซิร์ฟเวอร์ที่ทำงานต่อเนื่อง

## ความต้องการก่อนติดตั้ง

- Node.js เวอร์ชัน 18 ขึ้นไป
- npm
- MongoDB ที่เข้าถึงได้จากเครื่องหรือแพลตฟอร์มที่ deploy

## ติดตั้งและรันในเครื่อง

1. ติดตั้ง dependencies:

   ```bash
   npm ci
   ```

2. สร้างไฟล์ environment สำหรับเครื่องของคุณ:

   macOS หรือ Linux:

   ```bash
   cp .env.example .env
   ```

   Windows PowerShell:

   ```powershell
   Copy-Item .env.example .env
   ```

3. แก้ค่าใน `.env` โดยใช้ MongoDB URI ของคุณและสร้าง `JWT_SECRET` ใหม่ ห้าม commit ไฟล์ `.env` หรือส่งค่า secret ในแชต

   ```dotenv
   PORT=3000
   MONGO_URI=mongodb+srv://<username>:<url-encoded-password>@<cluster>/<database>
   JWT_SECRET=<random-secret>
   SESSION_DURATION_MINUTES=90
   SERVICE_CHARGE_PERCENT=10
   VAT_PERCENT=7
   ```

   ใช้รหัสผ่าน MongoDB ที่เข้ารหัส URL แล้ว หากมีอักขระพิเศษ เช่น `@`, `:`, `/` หรือ `#` ในรหัสผ่าน ส่วนชื่อฐานข้อมูลควรตรงกับฐานข้อมูลของร้าน

4. สร้าง CSS และเริ่มเซิร์ฟเวอร์:

   ```bash
   npm run build
   npm start
   ```

5. เปิดเว็บที่ `http://localhost:3000`

สำหรับโหมดพัฒนา ใช้ `npm run dev` ได้

## บัญชีทดสอบ

บัญชีต่อไปนี้มาจาก `seed.js` และจะถูกสร้างเมื่อเลือกติดตั้งผู้ใช้ด้วย `npm run seed` ในฐานข้อมูลทดสอบเท่านั้น

| บทบาท | ชื่อผู้ใช้ | รหัสผ่าน |
| --- | --- | --- |
| ผู้ดูแลระบบ | `admin` | `Demo@12345` |
| ผู้จัดการ | `manager` | `Demo@12345` |
| พนักงานครัว | `kitchen` | `Demo@12345` |
| พนักงานบริการ | `waiter` | `Demo@12345` |

**ห้ามใช้บัญชีเหล่านี้กับ Production หรือฐานข้อมูลที่มีข้อมูลจริง** บัญชีเหล่านี้เป็นข้อมูลทดสอบและมีสิทธิ์เปลี่ยนแปลงข้อมูลตามบทบาท หาก `seed.js` เคยถูกรันกับฐานข้อมูล Production ให้เปลี่ยนรหัสผ่านของบัญชีเหล่านี้ทันที และลบบัญชีที่ไม่จำเป็น

`npm run seed` เป็นคำสั่งแบบโต้ตอบ ตัวเลือกติดตั้งทั้งหมดจะเพิ่มข้อมูลเมนูและโต๊ะตัวอย่าง ส่วนการติดตั้งผู้ใช้จะตั้งรหัสผ่านบัญชีตัวอย่างข้างต้นใหม่ และการติดตั้งโต๊ะจะปรับสถานะโต๊ะตัวอย่างกลับเป็นค่าเริ่มต้น จึงควรรันเฉพาะกับฐานข้อมูลสำหรับพัฒนาและทดสอบเท่านั้น

## Environment Variables

| ตัวแปร | จำเป็น | ค่าเริ่มต้นหรือคำอธิบาย |
| --- | --- | --- |
| `PORT` | สำหรับรันในเครื่อง | พอร์ตที่เซิร์ฟเวอร์ใช้ ค่าเริ่มต้น `3000` |
| `MONGO_URI` | ใช่ | MongoDB connection URI |
| `JWT_SECRET` | ใช่ | secret สำหรับลงนาม JWT ต้องเป็นค่าที่สุ่มและไม่ซ้ำกับระบบอื่น |
| `SESSION_DURATION_MINUTES` | ไม่ | ระยะเวลาเซสชันเป็นนาที ค่าเริ่มต้น `90` |
| `SERVICE_CHARGE_PERCENT` | ไม่ | เปอร์เซ็นต์ค่าบริการ ค่าเริ่มต้น `10` |

สำหรับ Vercel ให้ตั้งค่าเหล่านี้ที่ **Project Settings → Environment Variables** ไม่ต้องอัปโหลดหรือ commit `.env` ตั้ง `MONGO_URI` และ `JWT_SECRET` เป็น Sensitive และเพิ่มค่าให้ environment ที่ต้องใช้ เช่น Preview หรือ Production หลังเปลี่ยนค่าแล้วต้อง deploy ใหม่เพื่อให้ฟังก์ชันใช้ค่าใหม่

MongoDB Atlas ต้องอนุญาตการเชื่อมต่อจาก Vercel ใน Network Access ด้วย ใช้ผู้ใช้ฐานข้อมูลที่มีสิทธิ์เท่าที่จำเป็น และอย่าเปิดการเข้าถึงแบบกว้างโดยไม่เข้าใจความเสี่ยง

## หมวดหมู่เมนูและการทดสอบส่วนติดต่อผู้ใช้

- รายการรหัสหมวดหมู่ร่วมกันอยู่ที่ `public/js/menu-categories.js` โดยฝั่ง Node.js ใช้ผ่าน `config/menuCategories.js` และ `config/constants.js` ไม่ต้องกำหนดรายการซ้ำในหน้าเว็บ
- เมื่อเพิ่มรหัสหมวดหมู่มาตรฐาน ให้เพิ่มคำแปล `menu.category.<รหัส>` ใน `public/locales/th.json` และ `public/locales/en.json` ด้วย
- ตัวกรองและแบบฟอร์มแก้ไขอ่านรหัสหมวดหมู่ที่มีอยู่ในข้อมูลจริงด้วย จึงรองรับหมวดหมู่เก่าและชื่อที่กำหนดเองโดยไม่เปลี่ยนเป็น “ไม่ระบุ” เมื่อบันทึกข้อมูลส่วนอื่น ไม่ต้องรัน seed หรือย้ายข้อมูลเดิมเพื่อใช้การแก้ไขนี้
- ปุ่มเปิดจอแสดงคิวเป็นลิงก์ไป `/display.html` ในแท็บใหม่จากการคลิกโดยตรง รองรับการเปิดผ่านคีย์บอร์ดหรือเมนูคลิกขวา และใช้ปุ่มเต็มหน้าจอในหน้าจอคิวได้ โดยไม่ตรวจจับการบล็อกจากค่าคืนของ `window.open()`

`npm run test:menu-ui` ใช้ `playwright-core` กับ Chrome/Chromium ที่ติดตั้งไว้ หากไม่พบเบราว์เซอร์ให้ตั้ง environment variable `CHROME_PATH` เป็นพาธไฟล์ executable ของ Chrome/Chromium ก่อนรัน การทดสอบนี้ใช้เซิร์ฟเวอร์ไฟล์และ API จำลองในเครื่อง ไม่ต้องใช้ `.env` หรือ MongoDB และไม่แก้ไขข้อมูลจริง

## วันทำการ เวลาปิดรับคิว และเลขคิวรายวัน

ร้านเปิด 10:30 ปิด 03:00 ซึ่งเป็น “วันทำการ” ที่ข้ามเที่ยงคืน ระบบจึงยึด **วันทำการ** ไม่ใช่วันปฏิทิน ในทุกจุดที่เกี่ยวข้อง:

- **วันทำการ** = วันที่ของ “เวลาเปิดร้าน” ล่าสุด เช่น เวลา 02:00 ของวันที่ 31 ยังนับเป็นวันทำการของวันที่ 30 (`utils/businessDay.js`)
- **เลขคิวรีเซ็ตที่ Q001 ทุกวันทำการ** ตัวนับแยกตามวัน (`queue-number:YYYY-MM-DD`) และคิวเก็บ `businessDate` + `sequence` โดย unique index คือ `{ businessDate, queueNumber }` ไม่ใช่ `queueNumber` เดี่ยว ๆ อีกต่อไป
- **ปิดรับคิว** ใช้ค่า `lastQueueTime` (ค่าเริ่มต้น 02:00) ซึ่งเร็วกว่าเวลาปิดร้าน ลูกค้าที่เข้ามาหลังเวลานี้จะได้ข้อความ “ปิดรับคิวสำหรับวันนี้แล้ว” แต่พนักงานยังเรียกคิว ชำระเงิน และเคลียร์โต๊ะได้จนถึงเวลาปิดร้าน (`middlewares/requireQueueAccepting.js`) ปรับได้ที่หน้า ตั้งค่า > เวลาให้บริการ > “ปิดรับคิวเวลา”
- **รายงาน/แดชบอร์ด** ยอดขาย ลูกค้า คิว และเวลาทานเฉลี่ย ใช้ช่วงวันทำการ `[เปิดร้านวันนั้น, เปิดร้านวันถัดไป)` และกราฟ 7 วันใช้ label เป็นวันทำการที่ API ส่งมา (`dates`)
- **หน้าคิวลูกค้า** แสดงแบนเนอร์ปิดรับคิวและปิดปุ่มรับคิวให้อัตโนมัติ โดยอ่านจาก `queueStatus` ใน `/api/settings/public`

### ระบบซ่อม index ให้เองเมื่อ deploy (กันเคส “คำขอไม่สำเร็จ”)

ฐานข้อมูลที่เคยใช้เลขคิวแบบ unique ทั้งระบบจะยังมี index เก่า `queueNumber_1` ค้างอยู่ พอเลขคิวเริ่มรีเซ็ตทุกวันทำการ คิวแรกของวันใหม่ (Q001) จะชนกับคิวของวันก่อนหน้า → MongoDB ตอบ duplicate key (E11000) → API ตอบ 400 → หน้าเว็บขึ้นแค่ “คำขอไม่สำเร็จ กรุณาลองใหม่”

ตอนนี้แก้ที่ต้นเหตุแล้ว 2 ชั้น เพื่อไม่ให้ต้องพึ่งการรันสคริปต์ด้วยมือ:

1. **ซ่อม index อัตโนมัติ** — ทุกครั้งที่แอปเชื่อมต่อฐานข้อมูล (`config/db.js`) ระบบจะเรียก `services/queueIndexes.js` ครั้งเดียวต่อโปรเซส: เติม `businessDate`/`sequence` ให้คิวเก่า, ลบ index เก่า `queueNumber_1`, และสร้าง index `{ businessDate, queueNumber }` ถ้ายังไม่มี (ถ้าฐานข้อมูลปกติจะข้ามแทบจะทันที)
2. **ออกเลขคิวแบบไม่ชน** — `services/queueNumbering.js` ออกเลขจากตัวนับรายวัน และถ้ายังตรวจพบ index เก่า จะเดินเลขต่อจากเลขสูงสุดที่มีอยู่จริงแทนการรีเซ็ต เพื่อให้ลูกค้ากดคิวได้เสมอ

ถ้ายังต้องการสั่งซ่อมเอง (เช่นตรวจสถานะก่อน) ใช้ `npm run queues:migrate-business-day` (dry run) แล้ว `node scripts/migrate-queue-business-day.js --apply` ซึ่งเรียกชุดคำสั่งเดียวกับที่แอปใช้

รหัสข้อผิดพลาดที่หน้าเว็บแสดงตรง ๆ แล้ว: `QUEUE_NUMBER_CONFLICT` (ระบบออกเลขคิวใหม่ ให้กดยืนยันอีกครั้ง) และ `INVALID_QUEUE_PAYLOAD` (ข้อมูลคิวไม่ถูกต้อง) — หน้าเว็บจะแสดง `message` ที่ API ส่งมาแทนข้อความกลาง ๆ เดิม

## วงจรชีวิตของคิว (waiting → called → seated → completed)

- สถานะคิวมีค่าจบรายการคือ `completed` เพิ่มจาก `cancelled` และ `no_show` เพื่อแยก “ทานเสร็จ/ปิดโต๊ะแล้ว” ออกจาก “ยกเลิก/ไม่มา” และไม่ให้คิวค้างในคอลัมน์ “นั่งโต๊ะแล้ว” ตลอดไป
- คิวจะถูกปิดเป็น `completed` อัตโนมัติเมื่อ **ชำระเงินสำเร็จ** (เงินสดและ QR), **เคลียร์โต๊ะ** (`POST /api/table/:id/clear`) และเมื่อ `reconcileState` พบคิวที่ผูกกับรอบที่จบไปแล้ว (รอบถูกยกเลิก หรือหมดเวลาเกิน 2 ชั่วโมง)
- พนักงานปิดคิวเองได้ด้วยปุ่ม **จบรายการ** บนการ์ด “นั่งโต๊ะแล้ว” (`POST /api/queue/:id/complete`) ซึ่งปิดเฉพาะรายการคิว ไม่แตะรอบรับประทานหรือสถานะโต๊ะ จึงไม่ปลดล็อกโต๊ะที่ยังมีลูกค้า
- การ์ดที่เลยเวลาที่กำหนดจะแสดงป้าย **เกินเวลา** พร้อม “นั่งมาแล้ว X นาที” แทนการนับถอยหลังที่ค้างอยู่ที่ 0:00
- หน้าร้านคิวของลูกค้าจะไม่แสดงข้อความ “กำลังรอพนักงานเรียกคิว” อีกเมื่อคิวถูกปิดแล้ว
- รายงาน “นั่งโต๊ะแล้ว” นับทั้ง `seated` และ `completed` เพื่อให้ยอดของวันไม่หายหลังชำระเงิน
- หากมีข้อมูลเก่าค้างอยู่ในฐานข้อมูล ให้รัน `npm run queues:close-stale` เพื่อดูรายการก่อน (dry run) แล้วรัน `node scripts/close-stale-queues.js --apply` เมื่อต้องการปิดจริง

## การอัปเดตข้อมูลและเสียงแจ้งเตือน

การ deploy แบบ Vercel Functions ของโครงการนี้ใช้ HTTP polling แทนเซิร์ฟเวอร์ Socket.IO ที่ทำงานต่อเนื่อง ส่วนการรัน `node server.js` บนเซิร์ฟเวอร์ที่รองรับยังใช้ Socket.IO ร่วมกับ polling สำรองได้ การเปลี่ยนข้อความสถานะไม่ได้เปิด WebSocket บน Vercel หรือย้ายระบบไปบริการภายนอก

ป้ายสถานะร่วมกัน (`public/js/live-updates.js`) แสดงตามผลโหลดข้อมูลจริง:

- **กำลังโหลดข้อมูล** — ยังไม่ได้รับข้อมูลครบสำหรับหน้าเว็บนั้น
- **อัปเดตทุก … วินาที** — โหลดผ่าน API สำเร็จ แต่ไม่ได้เชื่อมต่อ Socket.IO
- **อัปเดตแบบทันที** — เชื่อมต่อ Socket.IO และโหลดข้อมูลที่จำเป็นสำเร็จ
- **โหลดข้อมูลไม่สำเร็จ กำลังลองใหม่** — API ล้มเหลว ข้อมูลตอบกลับผิดรูปแบบ หรือเครือข่ายออฟไลน์ แม้ Socket.IO ยังเชื่อมต่ออยู่ก็ต้องแสดงข้อผิดพลาด การโหลดสำเร็จเพียงบาง API ไม่ล้างข้อผิดพลาดของอีก API

รอบอัปเดตออร์เดอร์ครัวคือ 20 วินาที; พนักงานเสิร์ฟ/โต๊ะ หน้าสถานะลูกค้า และแดชบอร์ดแอดมิน 30 วินาที; จอคิว 15 วินาที; รายการเมนูในหน้าครัว 60 วินาที การดึงข้อมูลไม่ใช้แคชและมี timeout 15 วินาทีเพื่อไม่ให้ค้างรอตลอดไป เมื่อกลับมาออนไลน์จะโหลดใหม่โดยไม่รอรอบถัดไป ทั้งนี้เบราว์เซอร์อาจชะลอ timer ของแท็บเบื้องหลังได้

แดชบอร์ดแอดมินรอรายงานทั้ง 5 ส่วนสำเร็จก่อนแสดงสถานะปกติ หากส่วนใดล้มเหลวจะเก็บข้อมูลรอบล่าสุดและแสดงข้อผิดพลาด ป้ายสถานะใช้สี่เหลี่ยมมุมมนเล็กน้อยในทุกสถานะ และเปลี่ยนภาษาแล้วไม่ย้อนกลับเป็น “กำลังเชื่อมต่อ”

หน้าครัวและพนักงานเสิร์ฟตรวจรายการใหม่จากข้อมูลที่โหลดสำเร็จ ไม่ว่าจะโหลดจาก polling, กดรีเฟรช หรือได้รับเหตุการณ์ Socket.IO จึงแจ้งเสียงได้ทั้งสองโหมด โดยมีหลักการดังนี้:

- ต้องคลิก/แตะหน้าเว็บหรือกดคีย์หนึ่งครั้งเพื่อให้เบราว์เซอร์อนุญาตเสียง ไม่พยายามข้ามข้อจำกัด autoplay
- การโหลดครั้งแรกใช้เป็นฐานเปรียบเทียบ ไม่เปิดเสียงกับออร์เดอร์/โต๊ะเก่าทั้งหมด
- ออร์เดอร์ใหม่ของครัว ออร์เดอร์พร้อมเสิร์ฟใหม่ และโต๊ะที่เปลี่ยนเป็นรอทำความสะอาดจะส่งเสียงเมื่อพบในรอบถัดไป
- ข้อมูลเดิม การเปลี่ยนภาษา การรีเฟรชซ้ำ หรือเหตุการณ์ Socket.IO ซ้ำไม่ทำให้ส่งเสียงซ้ำ โต๊ะเดิมแจ้งเตือนได้อีกเมื่อมีรอบทำความสะอาดใหม่
- เมื่อ API ล้มเหลว เก็บรายการล่าสุดไว้และแสดงสถานะผิดพลาด ไม่เปลี่ยนความล้มเหลวเป็น “ไม่มีออร์เดอร์”

ใช้ `npm run test:live-ui` เพื่อทดสอบพฤติกรรมเหล่านี้ด้วย API และเสียงจำลอง โดยตั้ง `CHROME_PATH` เช่นเดียวกับชุดทดสอบเมนู ไม่ต้องใช้ MongoDB และไม่แตะข้อมูลจริง
